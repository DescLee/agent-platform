## 2. 参赛目标

在 OpenWorker 开源项目基础上，以“绿巨人”为参赛产品名，完成面向“个人超级助理”赛题的合规二次开发和可验证交付。最终作品需要做到：

1. 满足模型配置、本地文件授权、内置技能验证等基础要求。
2. 形成一条完整、稳定、易演示的个人办公任务闭环。
3. 体现明确的赛事期间自主开发增量，而不是仅展示上游已有功能。
4. 提供源码、一键安装和启动脚本、数据库说明、可运行构建产物、测试报告、开发报告及完整演示录屏。
5. 在产品交互、架构成熟度、代码质量和全流程稳定性四方面形成可核验的评分证据。

## 3. 项目定位

### 3.1 参赛定位

安全治理型个人超级助理：在本地优先架构下，通过多模型、Skills、Memory、MCP、办公连接器和自动化能力完成真实工作，并以文件白名单、分级审批、自动审核和审计记录约束智能体行为。

### 3.2 核心演示闭环

```text
用户提出办公任务
  -> 选择并授权本地工作目录
  -> 助理调用模型、技能、本地文件和办公连接器
  -> 高风险操作触发审批或 Reviewer 复核
  -> 生成可直接使用的文档、表格或报告
  -> 保存必要记忆
  -> 可配置周期自动执行
  -> 在审计记录中追溯全过程
```

### 3.3 技术路线确认

- 桌面端采用 Tauri 2 + React + TypeScript。
- 本地 Agent 服务采用 Python sidecar，由 Tauri 负责启动、通信和退出清理。
- 主办方已口头确认 Electron 仅为建议，不作强制要求，以最终效果为准。
- 待办：保存主办方确认记录的截图或文字凭证，随开发资料归档。

## 10. 架构决策记录

| 编号 | 日期 | 决策 | 原因 | 影响 |
|---|---|---|---|---|
| ADR-001 | 2026-08-30 | 保留 Tauri，不迁移 Electron | 主办方确认技术栈不强制；迁移成本高且不增加最终效果 | 报告需重点解释 Tauri + Python sidecar 的合理性 |

| ADR-004 | 2026-08-30 | 参赛版暂命名为“绿巨人” | 与内部 IM“绿舟”形成后续协同联想，并表达“站在巨人的肩膀上做事” | 对外发布前需完成商标与品牌歧义评估 |
| ADR-005 | 2026-08-30 | 中文化仅改展示层与 Prompt，不改内部技术标识 | 避免破坏包名、协议、进程、更新服务和历史数据兼容性 | 报告中需解释展示品牌与内部兼容标识并存 |
